## Read these two first

- `docs/context/MAP.md` — generated by `npm run map`: every screen, migration,
  domain and database function, Swift module and Siri phrase in one page. Answer
  "where does X live" from here instead of opening files.
- `docs/context/FACTS.md` — what the code cannot tell you: Sideloadly, free Apple
  ID limits, Expo inline-module rules, the web preview's two gotchas. Read it
  before touching Expo, Swift, Siri, the widget or signing, and add to it when
  you learn something new.

## Project notes

- Personal iPhone expense tracker. Development happens on Windows without a Mac: test in Expo Go
  and build in the cloud with GitHub Actions (`docs/install-on-iphone.md`). Do not suggest steps
  that need Xcode locally.
- Run `npm run check` (type-check, lint, format check, snapshot-contract check, tests) before
  considering work done. `npm run preview` opens the web build with the headers `expo-sqlite`
  needs, on a fresh origin each run.
- After adding a screen, migration, domain function or intent, run `npm run map` and commit the
  regenerated `docs/context/MAP.md`.
- Money is always integer pence; format with `src/domain/money.ts` only at the UI edge.
- Expenses store a local calendar date (`YYYY-MM-DD`); use the helpers in `src/domain/dates.ts`.
- A budget period is not always a calendar month. Use `src/domain/period.ts` and the
  `useSelectedPeriod()` context, never `daysInMonth`/`monthRange`, for anything budget related.
- The Swift App Intents in `native/` read `Documents/budget-snapshot.json`, which
  `src/siri/budget-snapshot.ts` writes. Changing that shape means changing both sides;
  `npm run map:check` fails when they disagree.
- Business logic lives in `src/domain` as pure functions with tests in `__tests__`.
- Repositories in `src/db` take the `Db` interface so tests can run them on sql.js. Schema
  changes are new entries appended to `MIGRATIONS` in `src/db/schema.ts`; never edit a shipped
  migration.
- Screens read data with the hooks in `src/hooks/use-app-data.ts` and write through
  `useDbMutation`, which refreshes every query.
- Tests import `describe`/`it`/`expect` from `@jest/globals` (TypeScript 6 does not load global
  types automatically).
